## 4. Модель данных и функции

Основной объект системы — задача.

Каждая задача содержит следующие поля:

| Поле | Тип | Назначение | Ограничения |
|---|---|---|---|
| `id` | `number` | Уникальный идентификатор задачи | Положительное целое число |
| `title` | `string` | Название задачи | От 1 до 100 символов после `trim()` |
| `completed` | `boolean` | Статус выполнения | Только `true` или `false` |
| `priority` | `string` | Приоритет задачи | Только `low`, `medium`, `high` |

### Правила валидации

- id должен быть положительным безопасным целым числом.
- title должен быть строкой длиной от 1 до 100 символов после удаления пробелов по краям.
- completed должен иметь строго значение true или false.
- priority может принимать только значения low, medium или high.
- При добавлении задачи проверяется отсутствие другого объекта с таким же id.

### Результаты операций

При успешном выполнении операции изменения возвращается:
```bash
{
  ok: true,
  tasks: [...]
}
```

При ошибке:
```bash
{
  ok: false,
  error: "Описание ошибки"
}
```

Функция `findTaskById` возвращает найденную задачу либо `undefined`.

Функции `getPendingTasks` и `getTaskTitles` возвращают новые массивы.

Функция `getTaskStats` возвращает объект:
```bash
{
  total,
  completed,
  pending,
  progress
}
```

**Почему id не равен индексу:** 
`id` является идентификатором самой задачи и не зависит от её положения в массиве.

Индекс показывает только текущую позицию элемента. После удаления задачи индексы остальных элементов могут измениться, а их `id` должны остаться прежними.

Поэтому поиск задачи выполняется по `id`, а не по индексу массива.
**Почему getTaskStats возвращает число, а не строку с процентом:** 
`getTaskStats` возвращает числовое значение `progress`, чтобы его можно было использовать в дальнейших вычислениях.

Форматирование выполняется отдельно в main.js:

`progress.toFixed(1)`

Поэтому значение 50 остаётся числом, а при выводе отображается как `50.0%`.  
**Какие объекты копируются при изменении задачи:** 
При изменении задачи создаётся новый массив с помощью `map()` и новый объект изменяемой задачи с помощью spread-оператора:
```bash
{
  ...task,
  completed
}
```

Исходный массив и исходный объект задачи не изменяются.

При добавлении используется новый массив:

`[...tasks, newTask]`

При удалении:
```bash
tasks.filter(task => task.id !== id)
```

Таким образом, исходные входные данные сохраняются неизменными.

## 8. Расширение

**Выполнено:** вариант А — поиск задач по части названия.

Функция `searchTasks(tasks, query)` находится в отдельном модуле `src/task-extra.js` и подключена в `main.js`. Контракты девяти обязательных функций не менялись.

**Как работает функция:**
- из запроса удаляются пробелы по краям (`trim()`), затем он приводится к нижнему регистру (`toLowerCase()`);
- название каждой задачи тоже приводится к нижнему регистру, и проверяется вхождение запроса через `includes()`;
- результат сохраняет порядок исходного массива;
- пустой или пробельный запрос возвращает новый массив со всеми задачами (`[...tasks]`);
- в остальных случаях результат создаётся через `filter()`: это новый массив, а сами задачи не копируются и не изменяются.

**Проверки** добавлены в основной `checks.js` (строки «Расширение: поиск 01–08») и запускаются вместе с остальными командой `node practice-02/checks.js`.

## 9. Вывод

В работе реализованы девять функций для управления набором задач и дополнительная функция поиска `searchTasks`. По сравнению с ПР1 логика вынесена в отдельные функции, которые не выводят данные в консоль, а возвращают результат: значение, массив или объект `{ ok, tasks }` / `{ ok: false, error }`. Благодаря этому одни и те же функции используются и в `main.js`, и в `checks.js`, а ошибки обрабатываются как обычные данные.

Неизменность данных обеспечивается созданием новых массивов (`[...tasks, newTask]`, `map()`, `filter()`) и копированием изменяемой задачи через spread-оператор. Это подтверждено тем, что после всех сценариев `demoTasks` и `variantTasks` сохранили прежние id и количество задач, а в проверках входные данные заморожены через `Object.freeze`.

При первом запуске `checks.js` проходило 18 проверок из 35: функции вызывали неопределённые `isValidId`, `normalizeTitle`, `validatePriority` и `findTaskIndex`, а `renameTask` оставалась заглушкой. После исправления проходят все 46 проверок (35 общих, 3 собственные и 8 для расширения).
