## Эксперимент с очередями выполнения

До запуска `npm run example:order` записать прогноз порядка меток. После запуска внести фактический порядок и объяснить каждую позицию.

| Этап | Порядок меток | Объяснение |
|---|---|---|
| Прогноз до запуска | A-B-C-D-E-F | Предполагаемый порядок  |
| Фактический результат | A-B-C-D-E-F | Синхронный код выполняется первым, затем микрозадачи Promise, после них — callback таймера. |

Отдельно указать:

- **Синхронный код** — команды, которые выполняются непосредственно при запуске программы, без ожидания асинхронных операций. Они выполняются последовательно, поэтому соответствующие сообщения появляются первыми.

- **Очередь микрозадач** — в неё попадают обработчики Promise (`.then()`, `.catch()`, `.finally()`) и продолжения асинхронных функций после `await`. Они выполняются после завершения текущего синхронного кода.

- **Таймер с задержкой `0`** не выполняется немедленно, поскольку его callback ставится в очередь задач. Сначала JavaScript завершает синхронный код и обрабатывает очередь микрозадач, а затем переходит к callback таймера.

- **При удалении одного из обработчиков Promise** соответствующее сообщение исчезнет из вывода. Остальные обработчики продолжат выполняться, а порядок оставшихся сообщений сохранится с учётом зависимостей между операциями.

## Организация кода

Кратко описать ответственность файлов:

Файл | Ответственность |
|---|---|
| `api/server.mjs` | Создание и запуск API-сервера, обработка HTTP-запросов, предоставление маршрутов для задач, категорий и отладочных сценариев. |
| `src/api-client.js` | Реализация общего HTTP-клиента: формирование URL, отправка запросов, обработка HTTP-ответов, разбор JSON, тайм-ауты, отмена запросов и классификация ошибок. |
| `src/task-api.js` | Доменный модуль для работы с задачами и категориями. Содержит методы получения данных, нормализацию фильтров и проверку структуры ответов по контракту. |
| `src/variant.js` | Хранение номера индивидуального варианта и соответствующих фильтров для запроса данных. |
| `src/main.js` | Точка входа клиентской части. Создаёт API-клиент, подключает доменный модуль, выполняет загрузку данных и выводит результаты. |

**Почему `fetchFn` передаётся в `createApiClient`:**

Передача `fetchFn` позволяет отделить реализацию HTTP-клиента от конкретного способа отправки запросов. Благодаря этому можно использовать стандартный `fetch` или передать тестовую функцию, имитирующую ответы сервера. Это упрощает модульное тестирование и повышает гибкость кода.

**Почему HTTP-ошибки проверяются отдельно от сетевых:**

HTTP-ошибка означает, что сервер получил запрос и вернул ответ с неуспешным статусом, например `404` или `500`. Сетевая ошибка возникает, когда запрос не удалось выполнить или получить ответ, например из-за остановленного сервера. Разделение позволяет определить причину сбоя и выбрать подходящую обработку.

**Почему JSON проверяется по контракту после разбора:**

Успешный разбор JSON подтверждает только правильность синтаксиса данных. Он не гарантирует наличие необходимых полей и соответствие их типов ожидаемой структуре. Поэтому после разбора дополнительно проверяются обязательные свойства, типы значений, уникальность идентификаторов и согласованность метаданных.

## Реализация общего клиента

| Требование | Как реализовано | Проверка |
|---|---|---|
| Нормализация `baseUrl` | Удаление завершающих `/` с помощью `replace(/\/+$/, "")`. | Проверка соединения адреса с завершающим слешем и пути с начальным слешем. |
| Кодирование query-параметров | Использование `URLSearchParams` для формирования строки параметров. | Проверка пробелов, кириллицы, символа `&`, значений `false` и `0`. |
| Заголовок `Accept` | При отправке GET-запроса устанавливается `Accept: application/json`. | Проверка параметров вызова `fetchFn`. |
| Проверка `response.ok` | Если ответ неуспешный, создаётся `ApiError` с `kind: "http"`. | Запрос задачи `999` и `/debug/error`. |
| Проверка `Content-Type` | Проверяется соответствие типа содержимого формату JSON. | Запрос `/debug/text`. |
| Разбор JSON | Используется `response.json()`, ошибки разбора преобразуются в `ApiError` с `kind: "invalid-response"`. | Запрос `/debug/invalid-json`. |
| Ограничение времени | Используется `setTimeout` и `AbortController`. После истечения времени запрос отменяется. | Задержка 150 мс при тайм-ауте 20 мс. |
| Внешняя отмена | Переданный `signal` подключается к внутреннему `AbortController`. | Вызов `controller.abort()` во время запроса. |


## Классификация ошибок

| Сценарий | Ожидаемый `kind` | Фактические поля `ApiError` | Итог |
|---|---|---|---|
| Задача `999` | `http` | `status: 404`, `code: TASK_NOT_FOUND`, `details: { id: 999 }` | Успешно |
| `completed=yes` | `http` | `status: 400`, `code: INVALID_QUERY`, `details: null` | Успешно |
| `/debug/error` | `http` | `status: 503`, `code: SERVICE_UNAVAILABLE`, `details: null` | Успешно |
| `/debug/invalid-json` | `invalid-response` | `status: null`, `code: null`, `details: null` | Успешно |
| `/debug/text` | `invalid-response` | `status: null`, `code: null`, `details: null` | Успешно |
| Не запущен API | `network` | `status: null`, `code: null`, `details: null` | Успешно |
| Задержка больше тайм-аута | `timeout` | `status: null`, `code: null`, `details: null` | Успешно |
| Явный `AbortController.abort()` | `aborted` | `status: null`, `code: null`, `details: null` | Успешно |

Для ошибок, которые не являются HTTP-ответами, поля `status`, `code` и `details` имеют значение `null`. Поле `url` содержит адрес запроса.

В ходе проверки установлено, что HTTP-ошибки содержат статус ответа и код ошибки API, если они предоставлены сервером. Некорректный JSON, неподходящий `Content-Type`, тайм-аут и внешняя отмена корректно классифицируются отдельно.

## Доменный модуль задач

| Вызов | Результат |
|---|---|
| `getTasks()` | Получено 12 задач. ID: `[1, 4, 7, 10, 13, 16, 19, 22, 25, 28, 31, 34]`. |
| `getTasks({ completed: false, priority: "high" })` | Получено 3 задачи. ID: `[4, 13, 34]`. |
| `getTaskById(25)` | `{ id: 25, title: "Исправить обработку ошибок", completed: true, priority: "high", categoryId: 2 }`. |
| `getCategories()` | Получено 3 категории: `1 — Учёба`, `2 — Проект`, `3 — Организация`. |
| `loadInitialData()` | Получен объединённый результат `{ tasks, categories, meta }`: 12 задач, 3 категории, `meta.total: 12`. |

### Правила проверки данных

1. Задача должна быть объектом с положительным целочисленным `id`.
2. Поле `title` должно быть непустой строкой длиной не более 100 символов.
3. Поле `completed` должно иметь логический тип `boolean`.
4. Поле `priority` должно принимать одно из значений: `low`, `medium` или `high`.
5. Поле `categoryId` должно быть положительным целым числом.
6. Категория должна содержать положительный целочисленный `id` и непустое название `name` длиной не более 100 символов.
7. Идентификаторы задач и категорий должны быть уникальными в пределах соответствующих коллекций.
8. Поле `meta.total` должно быть неотрицательным целым числом и совпадать с количеством полученных задач.
9. Если ответ не соответствует ожидаемой структуре, создаётся ошибка `invalid-response`.

### Результат `loadInitialData()`

Параллельная загрузка вернула:

- `tasks` — 12 задач;
- `categories` — 3 категории;
- `meta.total` — 12;
- `meta.filters` — параметры фильтрации по умолчанию.

Таким образом, оба запроса успешно выполняются, а результаты объединяются в один объект.

4. **В обработчике ошибки** — анализ свойств итогового объекта `ApiError`.

Было установлено различие между основными типами ошибок:

- **Ожидание Promise** — асинхронная операция ожидает завершения через `await`. Само по себе ожидание не является ошибкой.
- **HTTP-ошибка** — сервер ответил, но вернул неуспешный HTTP-статус, например `404` или `503`.
- **Сетевая ошибка** — запрос не смог получить ответ от сервера, например из-за остановки API или отсутствия соединения.
- **Неверный ответ сервера** — сервер вернул ответ, который невозможно корректно использовать: некорректный JSON, неподходящий `Content-Type` или данные, не соответствующие ожидаемой структуре.
- **Тайм-аут** — запрос был автоматически прерван из-за превышения установленного времени ожидания.
- **Явная отмена запроса** — выполнение было остановлено по инициативе вызывающего кода с помощью `AbortController`.

Сравнение способов загрузки показало, что параллельное выполнение двух независимых запросов с помощью `Promise.all()` оказалось примерно в 2,1 раза быстрее последовательного выполнения.
